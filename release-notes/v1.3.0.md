The console launcher is its own executable. The pad-driven band that
`--console` opens - the tiles, the covers, the pad and keyboard input, the
selection glide - builds into **`ArmouryConsole.exe`**, a second binary of
the same crate from the same UI sources (`console_ui`, `art`, `pad`,
`pick`), so the daemon's `--console` mode and the standalone executable
cannot drift apart. The daemon **prefers the installed helper**:
`show_console` spawns the first helper module under `modules/<id>/` whose
recorded `entry` names `ArmouryConsole.exe` - the file name alone decides,
case-insensitively, lower id first, and a module whose executable is gone
from disk is skipped - logs the module's id, version and path, and falls
back to `current_exe() --console` when no helper is installed. The fallback
is the old path, unchanged in behaviour, so a machine with no console
helper runs its console exactly as before.

The console is installable as a catalogue **helper module**: an archive
carrying `ArmouryConsole.exe`, which the Modules window and the daemon
already download, verify and install. The helper runs as a child of the
daemon and inherits its elevation, so the SteamGridDB key stays where it
is - in the elevated daemon - and nothing in the key's pathway moved.

A failed catalogue check no longer clips its message. When a check fails
before any row is painted - a signature fetch or verification failure, or
no network at all - the message is painted where the rows would be, and
that line could run wide enough that the window edge cut it mid-URL. It
wraps now, the second arm of the fix that made the failed-download line
wrap in 1.2.0.

## What else changed

- The process-wide HTTP client, the system font install and the
  Per-Monitor-V2 switch moved into shared modules (`net.rs`, `fonts.rs`,
  `dpi.rs`), so the console binary links the UI and the HTTP client without
  the catalogue machinery. Same client, same fonts, same DPI switch - one
  more binary, no behaviour changed.
- The console binary carries the same icon and the same
  `requireAdministrator` manifest as the daemon - the build links the same
  resources into every binary of the crate - so a helper spawned by the
  daemon opens without a prompt, exactly like `--console` did.
- The **published catalogue is signed now** - the flip 1.2.0's notes called
  pending. The live manifest and its `.minisig` verify against the keyring
  baked into the binary, and the rows install as before.
- The release carries its two files as before: `ArmouryDaemon.exe` and its
  `ArmouryDaemon.exe.sha256` sidecar.

The pack format is unchanged, and the three shipped packs are the bytes they
were - Wallpaper Engine 1.4.0, G-Helper 1.3.1 and Rainmeter 1.5.0.
