# ArmouryDaemon 1.3.2

## The windows stay put, and a slow pack step no longer replays

**The dashboard comes to the front when the tray asks for it.** A tray click only sent a
focus request, and Windows refuses `SetForegroundWindow` from a process that was not the
last to receive input, so the window stayed behind whatever you had open. The daemon now
hands the UI's process the foreground right before it sends the request, and the UI raises
itself with a 400 ms always-on-top pulse that it drops again.

**Every window keeps its 5 pt frame.** The width came from per-row font estimates, which
miss what egui adds around a widget: a combo box with its arrow, or a button with its
padding, could end at the frame's edge and get clipped. The estimate is a floor now. Each
window measures what its laid-out body overflows by and grows by exactly that, held inside
the work area. The first attempt at this is worth recording, because it is what you saw on
30 Oct: counting the frame's own margins as overflow made the dashboard grow ten points a
frame until it covered the screen and Windows drew a title bar on it.

**A queued pack pass cannot replay behind a slow one.** Wallpaper Engine's
`-control stop` hung past the ten-second CLI deadline, was killed, and its stop only landed
on the next pass, so the OSD fired twice and the wallpaper changed half a minute late. The
deadline is 20 s, and the pack worker drops a queued full-state job when a newer one
arrives, because the newer state makes the older one obsolete. A tagged job, a disable or a
removal, keeps its turn.

**G-Helper stops warning about a switch that worked.** The read-back check ran after every
apply, and for a hotkey pack it could only measure G-Helper's own save delay. It now runs
for a pack with a script, where the pack writes the JSON itself. A scripted pack waits 3 s
for the file, which covers G-Helper's measured 2.5 s.

**Two helpers nothing called are gone**: `hotkey::apply` and `trust::len`/`source`. The
`cached`/`cached_hero`/`Repeat` helpers stay where they are, because the console launcher
uses them from its own binary.

## The counts

462 unit tests, none failing, run on the release machine. The daemon is still one
executable with no runtime to install; the console launcher, idle mode and killswitch still
come from the pack catalogue.

## The end of this line

1.3.2 is the last release of ArmouryDaemon. The modular work it was built for is done: the
daemon runs resident and elevated, the three packs and the three modules install from the
catalogue, and each one owns its own window, its own switch and, for a mode, its own key.
