# ArmouryDaemon 1.3.3

## The updater can download a whole release again

**The limit was the bug.** `update.rs` reads the release executable with ureq's
`read_to_vec()`, and that call carries a 10 MiB cap: 10,485,760 bytes. The 1.3.2 executable
is 13,495,808 bytes, so the download stopped partway through the body, every time, with

    update: cannot download .../v1.3.2/ArmouryDaemon.exe
    (the response body is larger than request limit: 10485760)

The fetch now sets its own ceiling, `MAX_BODY` at 64 MiB. That is four times the largest
build this project has produced and still a hard stop: a server cannot stream more than
that into the daemon's memory. Nothing about verification moved. The bytes are still
checked against the release's `.sha256` sidecar, and against the release signature wherever
one is present, before anything is written to `<exe>.new`.

**One manual install is still needed.** The flaw lives in the code that performs the
update, so 1.3.1 and 1.3.2 cannot download their way out: both fail on the 13.5 MB asset
before the fix can run. Install 1.3.3 by hand once. The release carries the executable and
its hash sidecar, so the download is verifiable, and updates work from there.

## The counts

462 unit tests, none failing. The daemon is still one executable with no runtime to
install; the console launcher, idle mode and killswitch still come from the pack catalogue.
