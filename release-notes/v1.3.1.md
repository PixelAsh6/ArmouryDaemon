# ArmouryDaemon 1.3.1

## The console launcher, idle mode and killswitch are modules now

They are no longer built into the daemon. Each one is downloaded from the packs
repository like any other module, appears in the Packs window and in the dashboard's
packs list, and has its own window behind the `‹` button:

- **Console launcher** — a helper module with its own executable: its window holds the
  open method (on pad connect / on daemon start / never), its pinned games and the
  SteamGridDB key for cover art, plus an on/off box.
- **Idle mode** — a mode pack: a hotkey (`home` by default), the black screens and every
  output muted. Any real key press ends it.
- **Killswitch** — a mode pack: a hotkey (`end` by default) that hides and mutes every
  running tracked app and puts them back when pressed again.

The daemon's hotkey table is now built from the installed, enabled mode packs. Nothing is
bound until the pack that asks for the key is installed, and disabling a pack takes its key
out of the table immediately. A mode's hotkey is recorded in its own window — typed or
captured, one to four keys (a modifier set plus the key) — and the hook is suspended while
recording, so recording Home does not also toggle the mode.

A mode runs on a tracked-app transition only when its manifest says
`"triggers": [{"kind": "tracked_app"}]`. The hotkey modes declare a hotkey instead, so a
game starting or closing can no longer run their blocks behind your back.

## The settings window lost three sections

The global hotkey editor, the console launcher's policy row and the SteamGridDB key all
moved into the modules' own windows. The settings window is timing, daemon, packs and the
logs/config buttons.

## Idle mode is an overlay and a mute — nothing else

It no longer reverts the packs when it comes up, re-applies them when it goes away, or
freezes switching while it is on. A tracked app starting or closing behind the black
screens leaves idle exactly as it is; the packs keep switching underneath.

The wake check also no longer mistakes an injected key for the user arriving. The old
`GetAsyncKeyState` poll could not tell a real keystroke from a `SendInput` one, and applying
a pack injects its own keys (G-Helper's mode chords), so starting a tracked app dismissed
the overlay. The low-level hook now records real key presses only.

## The chain really stands on one line

Placement was computed from the inner size the viewport was asked for; Windows adds a
border, so each window's outer bottom sat a few pixels below the dashboard's — under the
taskbar. Every chain window now measures its own outer rect and is corrected against the
dashboard's bottom edge, so Settings, Packs and every pack window share one baseline.

## Smaller fixes

- The packs count included only real packs, so the console helper made six modules read as
  five. The console row is listed and counted whether or not its helper is installed.
- The dashboard's idle-mode button is gone: idle is toggled by its own hotkey or the pack's
  Enabled box, like every other module.
- A pack row only draws a dropdown for a setting that has values; a mode's hotkey no longer
  renders an empty combo box.
- Each module's window says what it does instead of the tracked-app sentence it inherited.
- The CRLF trap: the catalogue's manifests are now written, hashed and signed as LF, the
  bytes the CDN serves, so a downloaded pack verifies.
- A stale UI test that depended on a removed permission-line argument was dropped.
